---
title: "Миграция с LibreLogin"
---

## Совместимость

- LibreLogin: протестирована версия `0.24.0`.
- Базы данных: SQLite, MySQL и PostgreSQL.
- Пароли: только `BCrypt-2A`.

Если найден пароль другого типа, BaronessAuth напечатает предупреждение и перенесёт профиль без пароля.

:::caution
Игрок не сможет войти без пароля, пока не привяжет аккаунт или администратор не установит ему пароль.

LibreLogin не хранит достаточно данных для определения premium-статуса. Все перенесённые профили получают `premium=false`.
:::

## Что переносится

- Последнее имя с исходным регистром из `last_nickname`;
- UUID из `uuid`;
- Пароль, если используется `BCrypt-2A`;
- Дата первого входа из `joined`;
- Дата последнего входа из `last_authentication`;
- IP последнего входа из `ip`.

LibreLogin не хранит IP первого входа. BaronessAuth установит `127.0.0.1`. Если последний IP отсутствует, для него тоже будет использован `127.0.0.1`.

Не переносятся `premium_uuid`, `secret` и `email`: в BaronessAuth нет соответствующих полей.

## Перед началом

1. Сделайте резервную копию базы данных и папки LibreLogin.
2. Установите последнюю версию BaronessAuth.
3. Поместите исходную папку LibreLogin в `plugins/`. JAR можно удалить: для миграции нужна только папка.
4. Проверьте настройки базы данных LibreLogin. Они должны указывать на базу, из которой нужно перенести игроков.

## Перенос

1. Выполните `/auth migrate LibreLogin`.
2. Следите за сообщениями в консоли, особенно за предупреждениями о неподдерживаемых паролях.
3. Дождитесь создания файла `.backup` с импортированными данными.
4. Загрузите его командой `/auth backup load [файл]`. При необходимости добавьте `--force`.

После загрузки проверьте несколько профилей и отдельно протестируйте вход игрока с перенесённым паролем.
